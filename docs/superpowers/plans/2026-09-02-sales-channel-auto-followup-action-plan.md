## 0. 배경과 결정 (2026-09-02)

### 목적 재확인
"AX 전환 컨설팅 3분 진단"(`/ax-check`)은 잠재 고객을 확보해 최종적으로 **컨설팅 계약**으로 잇는 영업채널의 전초기지다. 진단에 참여한 고객은 이후에도 뉴스레터·블로그로 계속 접촉하고, 문의가 자연스럽게 들어오는 구조를 만든다.

### 제약
영업이사는 1명이고 사무실보다 외부 고객 미팅 시간이 많다. 리드가 들어올 때마다 사람이 검토·작성·발송하는 구조는 지켜지지 않는다(2026-09-02 실기기 테스트 후 사용자 판단: "1영업일 내"는 절대적으로 무리, 별도 작성 부담도 큼).

### 결정
2026-08-30의 "상세본 자동 발송 철회 → 초안 자동 생성 + 영업이사 수동 발송"을 **다시 뒤집는다.** 단, 8/30 당시의 우려(내용이 부실한 채 자동 발송되는 "거짓 안내")는 질문지 v1 확정(`catalog.ts` v2, 2026-09-01)과 결과 피드백 구체화(답변 인용·업종 예시·3단계 로드맵)로 상당 부분 해소됐다고 본다.

- 진단 제출 후 **시스템이 영업일 기준 2~3일 내 상세 진단 메일을 자동 발송**한다.
- 영업이사는 메일을 작성하지 않는다. 역할은 **HOT 리드 직접 통화**와 `/admin/leads` 상태 갱신으로 좁힌다.
- 자동 발송 전에 영업이사(또는 사용자)가 개입할 수 있는 창(보류·수정·즉시 발송)을 둔다 — 기본값은 "자동", 개입은 예외.
- 첫 메일에 어떤 내용·문서를 실을지는 A단계에서 별도 검토한다(사용자 요청).

### 이 결정으로 바뀌는 것
| 항목 | 기존 | 변경 |
|---|---|---|
| 결과 화면 문구 | "담당 이사가 직접 검토해 영업일 기준 2~3일 내로 연락드립니다"(2026-09-02 커밋 `783b55b`) | 자동 발송에 맞게 정직하게 재수정(A-4) |
| SLA 미이행 감지 안전장치(백로그, 2026-09-02 등록) | 리마인드 알림 | **자동 발송으로 대체** — 별도 안전장치 불필요, 크론 실패 알림(Sentry)으로 흡수 |
| 2단계 2-2 LLM 상세 진단서 | 관리자 검토 후 발송 | 자동 발송 파이프라인 위에 얹는 **후속 개선**(응답 20건 이후) |

## 1. 설계 원칙

1. **사람이 없어도 리드는 방치되지 않는다.** 기본 경로에 사람의 손이 필요한 단계를 두지 않는다.
2. **영업이사의 시간은 "쓰기"가 아니라 "통화"에 쓴다.** 시스템이 등급을 이미 계산하므로 HOT에만 사람을 붙인다.
3. **자동이라고 거짓말하지 않는다.** "담당 이사가 직접 검토"처럼 지키지 못할 문구는 쓰지 않는다. 대신 "담당 이사가 직접 연락드릴 수 있습니다"처럼 참인 문장만 쓴다.
4. **동의 범위 안에서만 보낸다.** 진단 결과 안내(T0·T1)는 서비스 이행 메일로 보고, 그 이후 콘텐츠 메일(T2·뉴스레터)은 `marketingOptIn=true`인 리드에게만 보낸다. 이 구분은 `/privacy` 문구와 함께 법률 자문 또는 정보통신망법 광고성 정보 기준을 한 번 확인한다(A-6).
5. **첫 링크 발송(09/04)을 막지 않는다.** 자동화가 배포되기 전 들어오는 소수 리드는 과도기 규칙(5-0)으로 처리한다.

## 2. 팔로업 시퀀스 (제안)

| 터치 | 시점 | 방식 | 내용 | CTA | 대상 |
|---|---|---|---|---|---|
| **T0 결과 요약** | 제출 즉시 | 자동 | 화면에서 본 우선 과제 3가지 제목 + 결과 재열람 링크(`/ax-check/result/[token]`) + 소개서 PDF 링크 + "영업일 기준 2~3일 내 상세 진단 메일" 예고 | 결과 다시 보기 | 전원 |
| **T1 상세 진단** | D+2 영업일 09:30 KST | 자동(크론) — 발송 전 관리자 보류·수정·즉시 발송 가능 | `email-draft.ts` 구조 그대로: 답변 인용·업종 예시·3단계 로드맵·기대 효과 + 진행 방식(진단→설계→구축→교육) + 통화 제안 | 메일 회신 (3단계 이후 Calendly) | 전원(보류 건 제외) |
| **T1-HOT 병행** | T1 발송 당일 | **사람** | 영업이사 직접 전화. 알림 메일에 통화 포인트 3줄(가장 시간 드는 업무·검토 시점·의사결정 구조) 동봉 | 미팅 | HOT만 |
| **T2 너처** | D+7~10 영업일 | 자동 | 블로그 1편(2단계 2-5) 또는 익명 사례 + "궁금한 점은 회신" | 회신·문의 | `marketingOptIn=true`만 — **2차 구현(E)** |
| **T3 뉴스레터** | 월 1회 | 자동(Broadcasts) + 사용자 승인 | 3단계 3-2 그대로 | 문의·예약 | 옵트인 구독자 |

T0을 두는 이유: 현재는 고객 손에 남는 것이 화면뿐이다(고객 자동 메일이 8/30에 제거되어 재열람 링크도 전달되지 않음). T0은 비용이 거의 없고, "메일이 실제로 온다"는 첫 신뢰를 만든다. 사용자가 말한 "2~3일 이내 자동 메일"은 T1이다.

## 3. 첫 메일(T0·T1) 콘텐츠 검토 — 사용자 요청 "좀더 검토"

두 가지 안을 놓고 A-2에서 결정한다.

| | 안 A — 가볍게 + 상세 분리 (권장) | 안 B — 한 번에 상세 |
|---|---|---|
| T0 | 요약 3줄 + 재열람 링크 + 소개서 링크 | 상세본 전체 + 소개서 |
| T1 | 상세 진단 + 통화 제안 | 통화 제안만 |
| 장점 | 두 번 접촉, 각 메일이 짧음, "기다릴 것"이 생김 | 즉시 만족, 구현 단순 |
| 단점 | 크론 필요 | 화면과 동일 내용 반복, 두 번째 접촉 명분 약함 |

검토 체크리스트(안 확정 후 초안 2벌을 만들어 사용자·영업이사가 고른다):
- 제목 3안(예: "[CoreDXI] ○○의 AX 우선 과제 3가지 — 상세 진단", "3분 진단 결과를 정리해 보내드립니다")
- 발신자: `noreply@coredxi.com` 유지 + `reply-to`를 영업이사 메일로 (회신이 영업이사에게 바로 가도록)
- 소개서: 첨부 대신 **링크**(`/solutions` 다운로드 URL, 0-4 S4 게시 선행) — 스팸 점수·용량 회피
- 서명: `SALES_SIGNATURE` 실제 값(전화·메일) 확인 — 현재 미입력 상태
- 사람용 플레이스홀더(`[[통화에서 말씀 주신 ___]]`) 제거
- 모바일 가독성(카톡 인앱 브라우저에서 열림) — 텍스트 메일 기준 60자 줄바꿈
- 광고성 표기 필요 여부(원칙 4)

## 4. 기술 설계 요점 (B단계 설계 문서에서 확정)

- **데이터 모델**(`AxCheckResponse` 확장, 수동 `migration.sql` + `prisma migrate deploy`, `migrate dev` 금지):
  `followupStatus`(SCHEDULED / HELD / SENT / FAILED), `followupScheduledAt`, `followupSentAt`, `followupSubject`·`followupBody`(관리자 수정본, nullable), `followupError`
- **스케줄러**: Vercel Cron(`vercel.json` `crons`, 매일 00:30 UTC = 09:30 KST) → `/api/cron/ax-check-followup`. `CRON_SECRET` 헤더 검증, 멱등(SENT 재발송 금지), 1회 배치 상한, 실패 시 FAILED + Sentry 캡처. 대안으로 Resend `scheduledAt`도 가능하나 보류·수정이 안 되므로 크론 채택.
- **영업일 계산**: KST 기준, 주말 제외, 2026 잔여 공휴일 상수(추석 연휴 9/24~26 등). 단위 테스트 필수.
- **관리자**: `/admin/leads` 상세의 `EmailDraftPanel`을 "예정 발송 시각 · 보류 · 지금 보내기 · 본문 수정 · 발송 이력"으로 확장. EDITOR 권한으로 가능해야 한다.
- **알림 메일 개편**: 영업이사 알림에 초안 전문 대신 등급·통화 포인트·예정 발송 시각·관리 링크. HOT는 제목에 `[HOT]` 접두.
- **보안·품질(지침 5-4)**: 기존 rate limit 유지, 크론 라우트는 CSP nonce 무관(API), Sentry 20% 샘플링 적용, `url-safety.ts` 패턴은 외부 링크(Calendly) 도입 시 적용.
- **테스트**: Vitest — 영업일 계산·상태 전이·크론 핸들러(Resend 모킹)·T0 발송. Playwright — 기존 `ax-check.spec.ts` 골든패스에 "T0 메일 발송 호출" 확인 추가.
