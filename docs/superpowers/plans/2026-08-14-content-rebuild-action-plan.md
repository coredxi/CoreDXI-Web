## 0. 현재 상태

### 2-1. 항목 2 확인 결과 (2026-08-14)

코드 조사로 확인 완료, 추가 조치 불필요.

- `src/app/sitemap.ts`는 매 요청마다 `prisma.blogPost.findMany({ where: { status: "PUBLISHED" } })`로 동적 조회 — 게시물이 전량 삭제된 지금은 `/blog/[slug]` 항목이 자동으로 0개. 죽은 링크가 sitemap에 남아있지 않음
- `src/app/blog/[slug]/page.tsx`는 `if (!post) notFound();`로 구현되어 있어, 삭제된 slug로 접근하면 정상적으로 HTTP 404를 반환함. `revalidate = 60`이므로 배포 직후에도 최대 60초 이내에 반영됨
- 실사이트 확인: `https://www.coredxi.com/blog` 목록 페이지는 "아직 공개된 글이 없습니다" 빈 상태로 정상 렌더링, 깨진 링크나 에러 없음

## 2. 우선순위 판단 근거

- 항목 1(거버넌스)은 재발 방지가 최우선이므로 콘텐츠 발행보다 먼저 처리한다.
- 항목 2(기술 정리)는 사용자 경험·SEO 신호에 직결되므로 콘텐츠 재입고와 별개로 빠르게 확인 가능하다.
- 항목 3~4(콘텐츠 재입고)는 이미 검증된 파이프라인 산출물을 재가공하는 작업이라 신규 리서치보다 공수가 적다. 다만 항목 5(바이라인 정책)가 먼저 확정되어야 재가공 톤이 정해지므로, 5번은 3번과 병행하되 3번 산출물 발행 전에는 반드시 결정되어야 한다.
- 항목 8(대시보드 2단계)은 원래 일정(2~3주 데이터 누적 후)이 이번 사건과 무관하게 이미 2026-08-22 이후로 잡혀 있었으므로 일정 자체는 바뀌지 않는다. 다만 그 사이 블로그가 비어 있으면 누적되는 데이터의 대표성이 떨어지므로, 항목 3~4를 그 전에 시작해야 한다는 점을 명시적으로 문서화한다.
