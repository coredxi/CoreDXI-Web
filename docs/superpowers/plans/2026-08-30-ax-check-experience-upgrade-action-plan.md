## 1. 배경과 목적 (2026-08-30 사용자 지시)

영업채널 고도화의 목적은 **우리 회사의 AX 전환 컨설팅을 소개하고, 고객사가 AI·AX에 대한 거부감을 덜 느끼고 쉽게 접근할 수 있게 하는 것**이다. 이 목적에 비추어 현재 `/ax-check` 1단계 구현에서 세 가지를 보강한다.

| # | 개선 항목 | 지시 내용 |
|---|----------|----------|
| A | **인트로 화면** | 설문 첫 화면에 CoreDXI AX 전환 컨설팅에 대한 간략한 소개를 넣는다 |
| B | **피드백 구체화** | 설문 결과 피드백이 형식적 — 더 구체적이고 세부적으로 |
| C | **이메일 초안 워크플로우** | 피드백 이메일은 **초안만 자동 생성**하고, 실제 발송은 **영업이사가 직접** 한다 |

### 기존 결정과의 정합성

- **규칙 기반 유지(2026-08-22 결정 ②)**: B는 LLM 도입이 아니라 규칙 기반 카탈로그(`catalog.ts`)의 콘텐츠를 깊게 만드는 작업이다. LLM 진단서는 예정대로 응답 20건 누적 후 2단계에서 "관리자 검토 후 발송"으로 도입한다. C의 "초안 생성 → 사람이 검토 후 발송" 구조는 2단계 LLM 도입 시 그대로 재사용되는 워크플로우이므로 오히려 선행 정지작업이 된다.
- **⚠️ 기존 플로우 변경**: 원 설계 2번 시나리오 4단("같은 내용의 상세본이 메일로 간다")를 **철회**한다. 고객에게 자동 발송되던 상세본 메일을 없애고, 초안은 `/admin/leads`에서 영업이사가 확인·발송한다. 결과 화면의 "메일로 보내드렸습니다" 문구도 함께 바꿔야 한다(안 바꾸면 고객에게 거짓 안내가 됨 — **첫 링크 발송 전에 반드시 반영해야 하는 이유**).
- 영업이사 알림 메일(제출 시 `SALES_NOTIFY_EMAIL`로 발송)은 **유지**하고, 알림 본문에 고객용 초안 전문을 포함시켜 영업이사가 받은 편지함에서 바로 편집·전달할 수 있게 한다.

- **별도 게이트 화면이 아니라 같은 페이지 상단 섹션**으로 넣는다. 클릭 한 번이 늘면 완료율이 떨어지므로(가장 위험한 가정: "대표가 설문을 끝까지 채운다"), 스크롤 한 번으로 설문에 닿는 구조를 유지한다. 인트로 하단 "3분 진단 시작하기" 버튼은 폼 앵커로 스크롤.

## 4. 작업 B — 결과 피드백 구체화 (규칙 기반 유지)

### 설계 결정

지금 카드가 형식적인 이유는 답변 8개 중 3개만 반영되고 문장이 범용이기 때문. **LLM 없이** 다음 4개 축으로 카탈로그를 확장해 "우리 회사 얘기"로 읽히게 만든다.

1. **답변 인용(에코)**: 각 과제 카드 상단에 근거를 명시 — "'제안서·견적서 작성'을 가장 시간이 많이 드는 업무로 꼽으셨습니다." 선택지 라벨을 그대로 인용하면 규칙 기반이어도 개인화 체감이 가장 크게 오르는 지점.
2. **Q1(업종) × Q3(업무) 구체 예시**: 카드별 `industryExamples` 맵 추가 — 같은 "제안서 자동화"라도 AV 구축 업체에는 "장비 구성표·시공 내역 기반 견적 초안", 네트워크 업체에는 "BOM·회선 구성 기반 제안 초안"처럼 업종 언어로 1~2문장.
3. **firstStep → 미니 로드맵 3단계**: "첫 1주(데이터 정리) / 첫 1개월(도구 도입·파일럿) / 3개월(정착·측정)"으로 확장. Q2(규모)·Q4(성숙도)로 분기 — 예: 10명 미만이면 "전담자 없이 쓸 수 있는 SaaS부터", "전혀 없음"이면 "임직원 2시간 기초 교육부터".
4. **기대 효과에 범위 수치**: "제안서 초안 작성 시간 60~80% 단축(일반적 도입 사례 기준)"처럼 보수적 범위 + 출처 성격 명시. **과장 금지 — 확정 수치·보장 표현 사용 불가.**

`AxCheckSummary` 타입 확장(카드에 `echo`/`industryExample`/`roadmap[3]` 필드 추가), 화면(`/ax-check/result/[token]`)과 이메일 초안(작업 C)이 같은 데이터를 소비한다.

### 파일 단위 작업

## 5. 작업 C — 이메일 초안 생성 + 영업이사 수동 발송

### 설계 결정

- **고객 자동 발송 제거**: `submitAxCheck`에서 고객 대상 `sendResendEmail` 호출 삭제. 발송 실패 로깅 등 관련 코드도 정리.
- **초안은 저장하지 않고 조회 시점에 생성(on-demand)**: 새 모듈 `src/lib/ax-check/email-draft.ts`의 `buildCustomerEmailDraft(answers, summary, contact)` 순수 함수가 저장된 응답으로부터 초안(제목+본문)을 만든다. DB 컬럼·마이그레이션 불필요, 카탈로그를 개선하면 미발송 리드의 초안도 자동으로 좋아짐. (트레이드오프: 실제 발송본 기록은 영업이사 메일함에 남는 것으로 갈음 — `catalogVersion`은 응답에 이미 저장되어 있어 어떤 버전 기준이었는지 추적 가능)
- **`/admin/leads` 초안 UI**: 리드 상세에 "이메일 초안" 패널 — ① 전문 미리보기, ② **"초안 복사" 버튼(주 경로)**, ③ `mailto:` 링크("메일 앱에서 열기" — 보조 경로, 본문이 길면 잘릴 수 있어 복사가 기본). 발송 여부는 기존 상태(신규/연락함/미팅/종료)·메모로 관리(스키마 변경 없음).
- **영업이사 알림 메일에 초안 동봉**: 제출 알림 메일 본문 하단에 고객용 초안 전문 포함 — 영업이사가 관리자 페이지에 들어오지 않아도 받은 편지함에서 편집·전달 가능. (알림 메일은 계속 자동 발송)
- **결과 화면·인트로 문구 정합**: "상세 진단서는 입력하신 메일로 보내드렸습니다" → **"상세 진단서는 담당 이사가 직접 검토해 1영업일 내 메일로 보내드립니다"**. 인트로(작업 A)의 안내 문구와 통일.

### 이메일 초안 구성 (영업이사가 최소 수정으로 보낼 수 있게)

1. 인사 + 진단 참여 감사 (회사명·성함 자동 삽입)
2. 우선 과제 3가지 상세 (작업 B의 확장 카드: 에코·업종 예시·로드맵·기대 효과)
3. CoreDXI 진행 방식 1문단 (진단→설계→구축→교육)
4. 다음 단계 제안 + 영업이사 서명 블록 (서명은 `catalog.ts` 상수로 — 이름·직함·연락처)
5. `[[ ]]` 표시의 수동 편집 안내 슬롯 1곳 ("통화에서 말씀 주신 ___ 관련해서는…") — 영업이사가 개인화 한 줄을 넣도록 유도

### 파일 단위 작업

| 파일 | 작업 |
|------|------|
| `src/lib/ax-check/email-draft.ts` (신규) | 초안 빌더 순수 함수 + Vitest |
| `src/actions/ax-check.ts` | 고객 자동 발송 제거, 알림 메일에 초안 동봉 |

## 8. 리스크·유의사항

- **문구 불일치 리스크**: 결과 화면·인트로·초안·개인정보 동의 문구("진단 결과 발송 목적")가 서로 어긋나면 신뢰 손상 — C 반영 시 `/privacy` 동의 문구도 함께 점검("담당자 검토 후 발송"과 모순 없는지)
- **초안 방치 리스크**: 자동 발송이 없어졌으므로 영업이사가 초안을 안 보내면 고객은 아무것도 못 받음 — 알림 메일에 초안을 동봉하는 이유. 2단계에서 "N일 미발송 리드" 표시 등 보완 검토
- **기대 효과 수치**: 범위·출처 성격 명시 없이 확정 수치를 쓰면 컨설팅 신뢰도에 역효과 — 수용 기준에 명문화함
- **E2E 회귀**: 결과 화면 문구·메일 발송 로직 변경은 기존 Playwright 골든패스를 깨뜨림 — 같은 PR에서 반드시 수정
