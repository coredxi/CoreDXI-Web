## 1. 배경과 목표

2026-08-18 영업이사(비등기 임원, 위임계약)가 합류했다. 영업이사가 주로 접촉하는 고객은 **IT·통신·영상음향(AV) 시스템 구축 서비스 업체의 대표 또는 영업 담당자**다. 지금까지 coredxi.com은 "지인 소개 확인용 + 크몽·숨고 콜드 인바운드"(PRD 2번 ①·②) 두 채널만 서비스했는데, 이제 세 번째 채널이 생겼다.

③ **영업이사 아웃바운드** — 영업이사가 카카오톡·메일로 "솔루션 소개서 1장 + 인터뷰 링크"를 보내고, 고객이 3분짜리 질문지에 답하면 즉시 AX 기회 요약을 받는다. 사이트의 역할은 "발견"이 아니라 **"대화의 시작점을 만들고, 영업이사가 우선순위를 매길 수 있게 리드를 구조화"** 하는 것이다.

### 목표

| 구분 | 목표 |
|------|------|
| 영업 목표 | 영업이사가 **2026-09-05까지** 실전에서 링크를 보낼 수 있는 상태 도달. 응답 1건 = 구조화된 리드 1건(핫/웜/콜드 자동 분류) |
| 고객 경험 | 질문 8개·3분 이내 완료, 제출 즉시 화면에서 "우리 회사 AX 우선 과제 3가지"를 확인, 상세본은 메일로 수령 |
| 포지셔닝 | 솔루션 페이지를 "중소기업 AI 도입·AX 전환 컨설팅" 단일 오퍼 중심으로 재편 — 3종 카드 병렬 나열에서 "진단→설계→구축→교육" 단계형으로 |
| 리텐션 | 응답자가 곧 뉴스레터 구독자 — 월 1회 팔로업 발송으로 영업이사의 재접촉 구실을 만든다 |

### 이번 문서가 뒤집는 기존 결정

- **뉴스레터 발송 범위 제외(2026-08-08)** → **철회**. 단, "구독자 뉴스레터"가 아니라 **"영업이사가 접촉한 리드에게 보내는 월 1회 팔로업"** 으로 목적을 좁힌다(9번 참고). 발송 파이프라인은 3단계(10월)에 착수하며, 착수 시 별도 설계 문서를 추가로 쓴다.
- **예약/미팅 시스템(Phase 2 8번)** → 3단계로 앞당긴다. 진단 결과 화면의 CTA가 "영업이사와 30분 통화 예약"이 되어야 깔때기가 닫힌다.

### 이번 범위에 넣지 않는 것

- 회사 소개(`/about`) 전면 개편 — 2단계에서 레퍼런스 중심으로 "축약"만 한다. 영업이사가 보내는 링크는 `/ax-check`이지 `/about`이 아니다.
- 1단계의 LLM 기반 분석 — 1단계는 **규칙 기반 요약**(5번). LLM 분석은 응답 20건 이상 누적 후 2단계에서 붙인다(6번).
- 건설업 등 타 업종 질문지 — 동진기술은 지인 경유 예외 건이라 이 깔때기를 타지 않는다. 업종 추가는 Q1 선택지 + 예시 사전(`ax-check-catalog.ts`) 확장으로 가능하도록만 구조를 잡아둔다.

## 2. 사용자 시나리오

1. 영업이사가 통화 후 카카오톡으로 보낸다: "말씀드린 AX 진단 링크입니다. 3분이면 됩니다 — `https://www.coredxi.com/ax-check?ref=sales-kim`". 소개서 1장(PDF)을 함께 첨부한다.
2. 고객(대표/영업담당)이 모바일에서 연다. 업종 선택 → 반복 업무 고르기(예시가 라디오/체크박스로 제시됨) → 현재 AI 활용 수준 → 기대 효과 → 검토 시점 → 의사결정 구조 → 연락처·동의.
3. 제출 즉시 화면에 **"귀사의 AX 우선 과제 3가지"** 가 뜬다(규칙 기반). 하단 CTA: "상세 진단서는 입력하신 메일로 보내드렸습니다 / 30분 통화로 구체화하기".
4. 같은 내용의 상세본(과제별 기대 효과·첫 단계 제안·CoreDXI 진행 방식 1문단)이 메일로 간다. 영업이사에게도 알림 메일이 간다(문의 폼의 알림 패턴 재사용).
5. 영업이사는 `/admin/leads`에서 응답을 보고 핫 리드부터 전화한다. 상태(신규/연락함/미팅/종료)를 바꾼다.
6. 월 1회 팔로업 뉴스레터(3단계)가 응답자에게 간다 — 블로그 1편 + "이번 달 진단 참여 기업의 N%가 견적·제안서 자동화를 1순위로 꼽았습니다" 한 줄.

## 3. 질문지 설계 (v1 — IT·통신·AV 시스템 구축 업체용)

원칙: **8문항, 3분, 모든 문항에 예시 선택지**. 주관식은 "기타" 보조 입력 하나뿐. 문항 7·8은 고객에게는 맞춤 진단용으로 보이지만 내부에서는 리드 등급(BANT의 Timing·Authority)을 결정한다.

| # | 문항 | 형식 | 선택지(예시) | 내부 용도 |
|---|------|------|-------------|----------|
| 1 | 귀사의 주력 사업은 무엇인가요? | 라디오 | 네트워크·통신 인프라 구축 / 영상·음향(AV) 시스템 구축 / IT 인프라·SI / 유지보수·운영 서비스 / 위 복합 / 기타 | 예시 사전 분기 키, 향후 업종 확장 지점 |
| 2 | 임직원 규모는? | 라디오 | 10명 미만 / 10~30명 / 30~100명 / 100명 이상 | 제안 규모 힌트 |
| 3 | 가장 시간이 많이 드는 반복 업무는? (최대 3개) | 체크박스 | 제안서·견적서 작성 / 입찰 공고 탐색·서류 준비(나라장터 등) / 현장 실사 보고·도면·사진 정리 / 유지보수 민원 응대·이력 관리 / 납품·검수·준공 문서 / 거래처 관리·후속 영업 연락 / 기타(텍스트) | **우선 과제 매핑의 핵심 입력** |
| 4 | 현재 AI 도구 활용 수준은? | 라디오 | 전혀 없음 / 직원 일부가 개인적으로 ChatGPT 등 사용 / 팀 단위로 일부 업무에 사용 / 업무 시스템과 연동해 사용 | 성숙도 |
| 5 | 업무 데이터는 주로 어디에 있나요? | 라디오 | 엑셀·한글 파일(개인 PC·공유폴더) / 그룹웨어·ERP / 메신저·메일에 흩어져 있음 / 잘 모르겠음 | 첫 단계 제안 분기(정리 선행 여부) |
| 6 | AI 도입으로 가장 기대하는 효과는? | 라디오 | 제안·수주 속도 / 인건비·야근 절감 / 납품 품질·오류 감소 / 직원 역량 향상 / 신규 서비스 발굴 | 메시지 톤 |
| 7 | 도입 검토 시점은? | 라디오 | 3개월 내 / 올해 안 / 내년 이후 / 아직 정보 수집 단계 | **Timing** |
| 8 | 도입 결정은 어떻게 이뤄지나요? | 라디오 | 제가 결정합니다 / 대표(경영진) 보고가 필요합니다 / 아직 정해지지 않았습니다 | **Authority** |
| – | 연락처 | 입력 | 회사명(필수), 성함(필수), 이메일(필수), 휴대전화(선택) | 리드 식별 |
| – | 동의 | 체크박스 | (필수) 개인정보 수집·이용 동의 — 진단 결과 발송 목적 / (선택) AX 소식·팔로업 메일 수신 동의 | 선택 동의 = 뉴스레터 구독 연동 |

**리드 등급 규칙(v1)**

- HOT: Q7 ∈ {3개월 내, 올해 안} **and** Q8 ∈ {제가 결정, 대표 보고 필요} **and** Q3 선택 ≥ 2
- WARM: Q7 ∈ {3개월 내, 올해 안, 내년 이후} and 위 HOT 아님
- COLD: 나머지(정보 수집 단계 등)

등급 규칙과 문항은 모두 `src/lib/ax-check/catalog.ts` 한 파일에 데이터로 두어, 문구·선택지·가중치를 코드 구조 변경 없이 수정할 수 있게 한다(홍보팀/영업이사 요청 반영 경로는 `CONTENT_GUIDE.md` 17번에 기록).

## 4. 데이터 모델

`NewsletterSubscriber`와 같이 **Prisma 관리 신규 테이블**. 기존 Supabase 직접 테이블과 충돌 없음. 마이그레이션은 수동 `prisma/migrations/20260827120000_add_ax_check_response/migration.sql` + `prisma migrate deploy`.

```prisma
enum LeadGrade { HOT WARM COLD }
enum LeadStatus { NEW CONTACTED MEETING CLOSED }

model AxCheckResponse {
  id            String     @id @default(cuid())
  refCode       String?                      // ?ref= (영업이사 식별, 예: sales-kim)
  company       String
  name          String
  email         String
  phone         String?
  answers       Json                         // { q1: "...", q3: ["...","..."], ... } — catalog 버전 포함
  catalogVersion String                      // 질문지 버전 (v1)
  grade         LeadGrade
  score         Int                          // 규칙 점수(정렬용)
  summary       Json                         // 화면/메일에 보여준 우선 과제 3개 (재현 가능하도록 저장)
  status        LeadStatus @default(NEW)
  note          String?    @db.Text          // 영업이사 메모
  marketingOptIn Boolean   @default(false)   // 선택 동의 → NewsletterSubscriber 연동 여부
  resultToken   String     @unique           // /ax-check/result/[token] 재열람용(메일 링크)
  createdAt     DateTime   @default(now())
  updatedAt     DateTime   @updatedAt

  @@index([grade, createdAt])
  @@index([status])
  @@index([refCode])
  @@index([email])
}
```

- `marketingOptIn = true`이면 `subscribeNewsletter(email, "ax-check")`를 호출해 기존 구독 테이블에 합류시킨다(`source` 컬럼이 이미 있다). 별도 구독자 테이블을 만들지 않는다.
- 삭제 요청 대응: `/admin/leads`에서 hard delete 가능(개인정보 파기 의무), `/privacy`에 수집 항목·보유 기간(진단 발송 후 1년 또는 삭제 요청 시 즉시) 조항 추가.

## 5. 1단계 — 규칙 기반 요약 (LLM 없음)

`src/lib/ax-check/summarize.ts` (순수 함수, Vitest 대상)

- 입력: answers → 출력: `{ priorities: [{ title, why, firstStep, expectedEffect }] (최대 3개), grade, score }`
- Q3에서 고른 업무마다 카탈로그에 정의된 과제 카드(예: "제안서·견적서 작성" → "과거 제안서·견적 데이터 기반 초안 자동 생성 / 첫 단계: 최근 1년 제안서 20건 정리 / 기대: 작성 시간 50%↓")를 매핑. Q5가 "흩어져 있음/잘 모름"이면 모든 카드의 firstStep 앞에 "데이터 정리 1주"를 붙인다. Q6에 따라 expectedEffect 문장 톤을 고른다.
- 화면 요약은 3개 카드 + 등급과 무관한 중립 문구. 메일 상세본은 같은 데이터에 "CoreDXI 진행 방식(진단 2주 → 설계 → 구축 → 교육)" 1문단과 영업이사 연락처를 덧붙인다.
- 장점: 응답 즉시(수백 ms), 비용 0, 결과 재현 가능, 프롬프트 인젝션 무관. 단점: 조합 수가 적어 "맞춤" 느낌이 약함 → 2단계에서 보강.

## 6. 2단계 — LLM 상세 진단서 (응답 20건 이상 누적 후)

- 서버 액션에서 Anthropic API(또는 기존 스택에 맞는 제공자) 호출. 입력은 **카탈로그의 선택지 라벨과 기타 텍스트(최대 200자)만** — 사용자가 쓴 자유 텍스트는 시스템 프롬프트와 분리된 데이터 블록으로 전달하고 출력은 JSON 스키마로 고정(제목·과제 3개·첫 단계·기대 효과·주의사항). 출력은 **영업이사 검토 후 발송**(관리자 페이지에서 "상세본 보내기" 버튼)이 기본, 자동 발송은 품질 확인 후 전환.
- 화면 즉시 요약은 2단계에서도 규칙 기반 그대로 둔다(지연·비용·실패 시 폴백).
- API 키는 서버 환경변수, 실패 시 규칙 기반 상세본으로 그레이스풀 디그레이드(`resend.ts` 패턴).
- 비용 상한: 응답당 1회 호출, 재생성은 관리자만.

## 12. 열린 리스크

- **완료율 가정**: "대표가 카톡으로 받은 설문을 끝까지 채운다"는 검증되지 않았다. 1단계 배포 후 2주간 **링크 전송 수 대비 제출 수**를 영업이사가 수기로 기록(액션플랜 3번 표)해 20% 미만이면 문항을 6개로 줄인다.
- **질문지 품질**: 선택지 예시가 실제 고객 언어와 다르면 "우리 얘기가 아니네"가 된다. 0단계 인터뷰를 건너뛰지 않는다.
- **영업이사 도구 적응**: 관리자 패널 계정(EDITOR) 발급과 30분 사용법 안내가 필요하다. 도구가 쓰이지 않으면 깔때기는 존재하지 않는 것과 같다.
- **발송 결정 번복의 비용**: 8/8 결정을 뒤집는 만큼, 3단계 착수 전에 "누가 매달 쓰는가"(콘텐츠기획 담당자 지정)를 먼저 확정한다. 담당자가 없으면 3단계 발송은 다시 보류한다.
