## 1. 배경 — 무슨 일이 있었나

2026-08-14, 사용자가 운영 중인 별도 프로젝트("도구형 웹사이트 수익화 — 애드센스 포트폴리오")에서 `fiftyvibe.kr` 사이트가 구글 애드센스 광고 승인을 거절당했다. 같은 구글 계정에 `coredxi.com`도 함께 등록되어 있어 계정 단위 리스크 전이를 우려해 `coredxi.com`을 애드센스 대상에서 제외하는 과정에서, 기존 coredxi.com 블로그 게시물 대다수가 사용자가 웹서핑 중 다른 블로그에서 직접 복사·붙여넣기한 콘텐츠였음이 확인되었다. 저작권 문제 소지가 있다고 판단해 관리자 페이지(`/admin/blog`)에서 해당 게시물 전체를 삭제(hard delete)했다.

**중요한 확인 사항**: `coredxi.com`은 애드센스 수익화가 목적인 사이트가 아니라 B2B 리드 퍼널 자산(`CLAUDE.md` 로드맵 1층 — 컨설팅 기여)이므로, 애드센스 제외 조치 자체는 로드맵에 영향이 없다. 실질적으로 대응이 필요한 문제는 **블로그 콘텐츠 전량 소실**과 그 근본 원인인 **콘텐츠 소싱 프로세스 부재**다.

## 2. 근본 원인 진단

coredxi.com 블로그 콘텐츠는 별도 프로세스 없이 수동으로 만들어졌다. 반면 사용자가 별도로 운영 중인 네이버 블로그 콘텐츠 파이프라인(`C:\MyProjects\02_Agent\naver-blog`)에는 이미 다음과 같은 체계가 갖춰져 있다.

- 리서치(`research.md`) → 초안(`draft.md`) → 검토(`review.md`) → 조립(`final.md`/`final.html`) → 필요 시 QA(`qa.md`) 단계
- 문장 단위 출처 표기(예: "claude.com/product/cowork, 확인 2026-07-19")
- 통계·후기를 "공식 통계"와 "개인 체감 후기"로 구분해 신뢰도를 명시
- 산출물 검토 결과 이미 발행된 글 다수가 실제로 AI/Claude 생산성 주제를 다루고 있음이 확인됨

즉 이번 사건은 "새로운 콘텐츠 제작 역량이 필요한 문제"가 아니라, **이미 검증된 파이프라인이 coredxi.com에는 연결되어 있지 않았던 문제**다.

## 3. naver-blog 산출물 클러스터 분석

`output/` 하위 총 19개 소재 폴더를 확인한 결과 세 클러스터로 나뉜다.

| 클러스터 | 예시 | coredxi.com 적합도 |
|---|---|---|
| ① AI/Claude 생산성 (약 10편) | 클로드 코워크 사용법, 클로드 메모리 기능 활용법, MCP 서버 직접 만들기, Notion과 클로드를 활용한 업무 자동화, 클로드 스킬 만드는 법 등 | **높음** — AX 컨설팅 포지셔닝과 직접 정합, 원본 리서치·출처 검증 완료 |
| ② 바이브코딩/애드센스 수익화 | 바이브 코딩 도구 비교, 애드센스 사이트 추가 실전, 도구형 웹사이트 수익화 방안 | 낮음 — "피프티바이브"(개인 N잡 브랜드) 타겟(4050 직장인·N잡 준비자)용, B2B 의사결정권자와 불일치 |
| ③ 정책·경제 일반 | 기본소득 지역 확대, 최저임금 실수령액, 일용근로소득 건강보험료 | 없음 — AI/AX와 무관한 범용 SEO 소재 |

결론: **①클러스터만 CoreDXI 톤으로 재가공해 반영**하고, ②③은 가져오지 않는다.

## 4. 브랜드 구조 결정

### 4-1. 검토한 옵션

| 옵션 | 내용 | 채택 여부 |
|---|---|---|
| A. 완전 통합 | 피프티바이브(개인) = CoreDXI의 얼굴. 동일 인물·동일 서사로 노출 | 기각 — 리퍼럴 리드가 사이트에서 "신뢰 확인"을 할 때, 개인 부업 브랜드 이미지가 오히려 혼선을 줄 위험 |
| B. 완전 분리 | 두 브랜드 간 어떤 콘텐츠도 교차하지 않음 | 기각 — 이미 확보된 ①클러스터라는 자산을 활용하지 못함, 크몽·숨고+팔로워 인바운드 전환 채널을 포기하는 셈 |
| **C. 선택적 콘텐츠 브릿지 (채택)** | 브랜드 정체성·계정·리스크는 분리 유지. ①클러스터 콘텐츠만 CoreDXI 톤으로 재서술해 단방향으로 흐르게 함 | **채택** |
| D. CoreDXI 하위 이니셔티브화 | 사용자가 준비 중인 "CoreDXI 공식 인스타그램"을 별도 페르소나로 성장시켜 장기적으로 C안을 보완 | 채택(C안과 병행, 장기 과제) |

### 4-2. 채택 근거

사용자가 확인한 리드 유입 채널은 두 갈래다.

1. **지인 소개·네트워킹(현재 진행 중인 컨설팅 계약의 실제 경로)** — 이미 신뢰가 형성된 상태로 유입. coredxi.com의 역할은 "설득"이 아니라 "확인"이며, 여기서는 전문적·신뢰감 있는 톤이 콘텐츠 물량보다 중요하다.
2. **크몽·숨고 리스팅 + 팔로워 문의(사용자가 기대를 걸고 있는 채널)** — 사전 신뢰 없이 콘텐츠·포트폴리오만으로 판단해야 하는 콜드 인바운드. 여기서는 콘텐츠 물량과 전문성 증명이 결정적이다.

두 채널이 파는 상품은 규모만 다를 뿐 **동일한 역량(AI/AX 전환 컨설팅 및 서비스 구축)**이라는 점이 사용자에 의해 확인되었다. 따라서 ①클러스터(실전 AI 활용 증명)는 두 채널 모두에 통하는 단일 신뢰 자산이 될 수 있다. 완전 통합(A)은 채널 1의 신뢰 확인 기능을 해칠 위험이 있고, 완전 분리(B)는 채널 2의 전환 자산을 포기하는 셈이라 C안(+D안 병행)으로 결정한다.

## 5. 콘텐츠 재가공 원칙

- **바이라인**: "CoreDXI 팀" 또는 "CoreDXI 인사이트" 명의로 통일 발행. "김부장의 OO기" 같은 개인 브랜드 1인칭 서사는 CoreDXI 콘텐츠에서 제거하고, 실무 경험 자체는 "저희 팀이 실전에서 확인한 바로는" 식으로 법인 주어로 재서술한다. **대표 개인 실명은 병기하지 않는다(2026-08-14 확정)**.
- **출처 유지**: naver-blog 원본의 출처 표기(참고자료 목록, 확인일자)는 그대로 유지한다 — 이번 사건의 재발 방지 원칙과 직결.
- **CTA 추가**: naver-blog 원본에는 없는 CoreDXI 전환 CTA(`/contact`, 뉴스레터 구독)를 글 하단에 추가한다. 기존 GA4 이벤트 태깅 체계(`cta_click`, `newsletter_subscribe`)를 그대로 재사용한다.
- **비대상 클러스터 처리**: ②③클러스터는 coredxi.com에 게시하지 않는다. 필요 시 별도 검토.

## 6. 콘텐츠 거버넌스 — 재발 방지책

`CONTENT_GUIDE.md`에 다음 원칙을 명문화한다(별도 커밋으로 반영).

1. 외부 사이트의 문장·문단을 그대로 복사해 coredxi.com 블로그에 게시하는 것을 금지한다.
2. 신규 블로그 글은 (a) naver-blog 파이프라인 산출물을 재가공하거나, (b) 동등한 수준의 원본 리서치(출처 표기 포함)를 거쳐야 발행할 수 있다.
3. 인용이 필요한 경우 출처를 명시하고 원문 전체가 아닌 요약·재구성으로 작성한다.

## 7. Phase 1 로드맵과의 관계

`docs/TODO.md` 기준 Phase 1의 GA4 전환 이벤트 태깅(1단계)은 2026-08-08에 이미 완료되어 데이터가 누적 중이며, 2단계(퍼널 시각화 UI)는 "2~3주 데이터 누적 후" 착수 예정으로 원래도 대기 상태였다(2026-08-08 기준 2026-08-22~29경). 이번 콘텐츠 재건 작업은 이 대기 기간과 자연스럽게 병행할 수 있다.

다만 블로그가 완전히 비어 있는 상태로 2~3주를 보내면, 정작 대시보드가 보여줄 시점에 콘텐츠 기여 트래픽이 거의 없는 데이터가 쌓이게 된다. 따라서 **콘텐츠 재입고 스프린트(①클러스터 발행)를 대시보드 2단계 착수보다 먼저 또는 최소 동시에 시작**할 것을 권장한다. 상세 일정은 `docs/superpowers/plans/2026-08-14-content-rebuild-action-plan.md` 참고.
